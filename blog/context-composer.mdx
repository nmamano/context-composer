In this post I describe [Context Composer](https://github.com/nmamano/context-composer), a tool that lets you do **live, model-unaware surgery on a real agent's context**. You chat with Claude Code in one window; in another, you delete a tangent, compress a wall of tool output into one line, or park a 2,000-token turn in a file — and the next message the model sees reflects all of it. The agent never finds out.

I previously wrote about [context engineering](/blog/context-engineering) as one of the two levers you have over LLM output quality. This project is that post taken literally: if context is what matters, you should be able to *edit it* — like a document, not like a chat log you can only append to.

## The premise

Coding agents accumulate junk. A wrong-direction exploration, a 50KB tool result that mattered for exactly one turn, a tangent about lunch — it all stays in the context forever, degrading attention and costing tokens on every subsequent turn.

The standard answers are blunt: `/clear` (lose everything) or `/compact` (lose control over *what* survives). What I wanted was scalpel-grade control:

<Callout>
  Your agent's conversation should be an **editable sequence of frames** — one
  per turn — that you can delete, rewrite, compress, reorder, split, and merge
  mid-session, **without the agent or the model knowing the tool exists**.
</Callout>

The "without knowing" part is the interesting constraint. No forked client, no SDK integration, no plugin. The wrapped agent is a stock Claude Code install; it believes it's talking to the regular API.

## The trick: intercept the resend

The whole design rests on one asymmetry of how chat agents work: **the client resends the entire conversation on every turn**. The model is stateless; "the conversation" is just a string the client rebuilds each time.

That resend is the interception point. Context Composer is a proxy that sits at the `ANTHROPIC_BASE_URL` boundary:

```
Claude Code  ──►  Context Composer (proxy)  ──►  Anthropic API
                  decompose → reconcile →
                  apply your edits → compose
```

Each incoming `/v1/messages` request gets **decomposed** into frames (the system prompt + tools become a *preamble* frame; each user-message-plus-reply becomes a *turn* frame), **reconciled** against the authoritative frame store, and **recomposed** with your edits applied before forwarding upstream.

Pointing the agent at it is the entire setup:

```bash
bun run proxy                                     # the daemon
ANTHROPIC_BASE_URL=http://localhost:8788 claude   # a stock Claude Code
```

Auth rides through untouched — the proxy is credential-agnostic, so your existing subscription session just works. No API keys.

## Reconciling with a client that doesn't know

Here's the hard part, and where most of the engineering went. The agent is *unaware*. After you delete turn 3, the agent — which still believes turn 3 happened — **resends it on the next request**. A naive proxy would happily re-add it.

So deletion can't be deletion. A deleted frame becomes a **tombstone**: it stays in the store as a *match target*, so the agent's resend reconciles against it (and emits nothing), instead of looking like new content. The same one-to-one matching principle handles edits (the agent keeps resending the original; the proxy keeps emitting your version) and offloads.

Identity is the other landmine. How do you know two requests belong to the same conversation, when a real agent multiplexes side queries — title generation, quota probes — over the same endpoint? My rule, after some pain:

<Callout>
  Identity must be **derived, never guessed from content**. A conversation is
  keyed by its opening turn's fingerprint — the one part of a request that is
  byte-stable across the agent's lifecycle, because history only appends.
</Callout>

The system prompt is deliberately *not* part of identity. Live wiretap evidence showed Claude Code embeds a per-invocation billing hash in a system block — it re-keys on every process restart. Keying on the head would fork your conversation every time you resumed a session.[^billing-line]

[^billing-line]: That billing line caused a second, funnier bug: the engine's "did the head change?" detection fired on *every single request*, because the head really did change every time — by exactly one volatile attestation hash. The audit log dutifully reported the system prompt as "grown" forever. The fix is a deliberately narrow exception: the change-detection signature ignores that one line, while the stored bytes and the forwarded wire stay faithful (the attestation must ride — it's the client proving it's a real client).

## Frames and the operation catalog

Everything the model receives is a frame; there are no special frame types and no protected regions.[^no-guardrails] One frame for the preamble (system prompt + tool definitions — in a Claude Code session that's ~50K tokens, by far the biggest frame), one per turn, with the turn's whole tool loop bundled in.

[^no-guardrails]: Yes, you can delete the system prompt. It breaks the session in interesting ways (the API starts rejecting requests), and `revert` heals it in place. The tool's philosophy is total control by capture, not constraint — guardrails are the daemon refusing *incoherent* operations (editing an absorbed frame), never *dangerous-but-coherent* ones.

The operations, all available from both the CLI and the browser:

- **`delete`** / **`revert`** — remove a frame; undo any past operation.
- **`edit`** / **`compact`** — replace what the model sees (whole frame, or swap it for a short summary).
- **`offload`** / **`restore`** — park a frame's content in a file; a stub with the file path takes its place, so the *agent can read it back on demand* with its own file tools. Poor man's memory hierarchy.
- **`add`** / **`move`** — inject a note anywhere; reorder frames.
- **`combine`** / **`split`** — merge frames; cut one into parts.
- **`strip`** / **`summarize`** — drop or summarize bulky tool results *inside* a frame.
- **`retitle`** — display metadata (titles and summaries are auto-generated per turn, but your manual edits always win).

## Two views, one truth

The browser UI has a conversation view (the chat as the model currently sees it), the frame view above (the manipulation surface), and a history tab. The design rule that kept it honest:

<Callout>
  The UI is a **thin wrapper**: it re-states engine decisions, never re-decides.
  Membership and order come from the engine's compose; no operation exists in
  the UI that the CLI lacks — and that parity is **enforced by a test that
  diffs the op registry against the CLI's verb table**, not by good intentions.
</Callout>

The second half of that rule: **guards speak**. The UI never disables a button because it predicts the daemon would refuse; it sends the request and renders the daemon's refusal verbatim. The one place I bent this — `restore` only makes sense on offloaded frames — the fix was *relocation*, not hiding: the restore button lives on the "offloaded" chip itself, the way a revert button lives on a commit card.

## War story: the no-content-heuristics rule

Early on I locked a principle: the engine never makes decisions by *reading the content* of frames. Identity comes from structure, membership from the wire, state from explicit operations. Content heuristics are how tools become haunted.

The rule earned its keep by being violated — twice, deliberately, with sign-off:

1. **The suggestion-mode marker.** Claude Code sometimes appends a synthetic turn starting with `[SUGGESTION MODE:` that never joins the main thread. Structurally, you can only detect this one request *too late*. We allowed one prefix check — and promptly shipped it wrong, because the literal was transcribed from my prose description (`*[SUGGESTION MODE` — the asterisks were my markdown emphasis, not wire bytes). The fix produced a better rule than the original principle: **marker literals come from the wiretap, never from prose**.
2. **The billing line** from the footnote above.

Both exceptions are marked in the code as exceptions, with the brittleness contract written down: if the client changes formats, behavior degrades to exactly what it was before the exception existed.

## Meta: built by agents, gated by an agent

Context Composer was built almost entirely by agents running in [Isomux](/blog/isomux), and the process is the part I'd actually generalize. Two pieces:

- **A durable feedback ledger.** I test the UI and fire off complaints in chat; every report immediately becomes a numbered entry in a markdown ledger (`F-001` through `F-074` so far) with verbatim quotes, triage class, and eventually the fix evidence. Chat is ephemeral; the ledger survives context resets and is the single source of truth for "what did Nil actually ask for."
- **A reviewer agent with real teeth.** Every batch of changes goes to a separate reviewer agent for a plan gate (before risky work) and a diff review (before every commit). Nothing lands without sign-off. This sounds like theater until the reviewer blocks your commit because a checkmark could flash on a failed refresh, or because your screenshot script could hijack a daemon it didn't start if the port was taken. Both real, both caught, both pre-commit.

The numbers from one day of this loop: ten reviewer-signed commits, three of them engine changes behind plan gates, every reviewer finding fixed before landing.

## Honest limitations

- **It doesn't save you money by existing.** The proxy forwards faithfully; editing the context down is what saves tokens, and that's on you. (Offloading the 53KB preamble is the dramatic demo — but it also busts the provider's prefix cache, which wants your head byte-stable. The tool keeps the head stable *unless you explicitly mutate it*.)
- **Single branch, for now.** Branching/checkout (fork the context, explore, import the good frame back) is designed but deliberately re-sequenced after the UI.
- **Identity has a documented collision**: two conversations opening with byte-identical first messages merge. Visible in the conversation list, accepted for now.
- **Provider assumptions.** It speaks the Anthropic wire format. The frame model isn't provider-specific, but the decompose/compose layer is.

## Takeaways

If you're building anything that manipulates an unaware client's traffic:

- **Intercept at the boundary you don't control.** An SDK integration would have been easier and useless — the proxy works with a stock client, which is the entire value.
- **The resend is your friend.** Stateless-model-plus-full-resend means you get a fresh reconciliation opportunity every turn. Tombstones beat deletion.
- **Derive identity from structure, never content.** And when you must break the rule, break it narrowly, mark it in code, and write down the degradation contract.
- **Evidence beats reasoning about wire formats.** Every literal, every "the client sends X" claim — read it from the wiretap. My one transcribed-from-prose literal shipped broken.
- **Audit everything, refuse loudly.** A tool that silently edits context must be the *least* silent tool you own, everywhere else.
